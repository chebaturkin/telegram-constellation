# telegram constellation

карта ваших разговоров из локального экспорта telegram. посмотрите связи между чатами и участниками, найдите нужное имя и разберите активность по времени. файл остаётся в браузере.

[открыть telegram constellation](https://chebaturkin.github.io/telegram-constellation/)

можно начать без своего архива: нажмите «открыть пример». все имена и разговоры в нём вымышлены.

## как пользоваться

1. откройте пример или выберите `result.json`. файл также можно перетащить в область загрузки.
2. переключайтесь между чатами и участниками. размер точки показывает число сообщений, коралловый цвет выделяет высокую активность.
3. нажмите на точку или найдите имя в списке. над картой появятся детали, а связанные точки останутся выделенными. список связанных узлов позволяет перейти к соседнему участнику или чату.
4. раскройте фильтры для выбора чата, участника, дат или типов связей. можно оставить ответы и упоминания, убрав общие чаты и близость по времени. на шкале можно выбрать месяц; повторный выбор снимает период.
5. скачайте текущую карту в svg или png. «удалить данные» очищает страницу и возвращает первый экран.

кнопка «как получить архив» объясняет экспорт из telegram desktop. «как читать карту» открывает легенду и подсказки по клавиатуре.

## приватность

- файл читается через браузерный file api и не отправляется на сервер;
- импорт работает без telegram api, аккаунта, аналитики и внешних моделей;
- тексты сообщений не сохраняются в модели, адресе страницы, логах и скачанной карте;
- после разбора остаются имена, даты, счётчики, идентификаторы и типы связей;
- данные хранятся только в памяти открытой страницы. перезагрузка или удаление данных очищает карту;
- ошибка нового импорта и отмена сохраняют уже открытую карту;
- шрифты и вымышленный пример находятся в репозитории. сторонние ресурсы при работе карты не загружаются.

## какие экспорты поддерживаются

- `{ "chats": { "list": [...] } }` с несколькими чатами;
- один объект чата с `messages`;
- массив сообщений с полями отправителя, дат, ответов и упоминаний.

карта строит связи по ответам, упоминаниям, общим чатам (для участников), общим участникам (для чатов) и близости по времени. несколько типов связи могут соединять одну пару точек. в режиме «авто» смешанный экспорт открывает чаты, а один чат — участников; переключатель позволяет изменить слой.

пустые и повреждённые записи пропускаются. невалидные календарные даты не попадают на шкалу. если подходящих сообщений не осталось, интерфейс объясняет ошибку и сохраняет предыдущую карту.

## запуск локально

из корня проекта:

```bash
python3 -m http.server 4175
```

откройте `http://127.0.0.1:4175/`. сервер раздаёт статические файлы; обработка архива происходит в браузере.

браузерные проверки и скриншоты используют python playwright и chromium. установите их в окружение, если они ещё не доступны:

```bash
python3 -m pip install playwright
python3 -m playwright install chromium
```

fixture-файлы в `fixtures/` проверяют корректный импорт и ошибку формата. новый сценарий проверяет пример, поиск, выбор узла, переключение слоёв, даты, скачивание, очистку, отсутствие сторонних запросов и ширины 320, 375, 768 и 1440 px. скриншоты выше сняты с работающего приложения в chromium, а не с макета.

## ограничения и устройство

движение карты следует связям: выбранная точка отмечается коротким контуром, а импульс проходит к её соседям. откройте пример и выберите имя, чтобы увидеть этот отклик. фильтры сохраняют места знакомых точек; нажатие сжимает только декоративный ореол, оставляя область ввода неподвижной. переключатель слоёв, шкала периода, кнопки и загрузка получают более тихий отклик. при reduced motion программные и css-анимации отключаются, выбор остаётся понятным по контуру и тексту. svg и png содержат конечное состояние без временной графики.

файл читается целиком в браузере. максимальный размер — 250 мб. zip-архив сначала нужно распаковать локально и выбрать `result.json`.

шкала показывает месяцы для выбранного чата или участника. при выборе дат она сохраняет весь контекст, чтобы можно было перейти к другому месяцу. сообщения без дат учитываются в общем количестве, но не попадают на шкалу.

`app-data.js` экспортирует `parseExport(input)`, `normalizeModel(parsed)`, `deriveRelations(model)` и `filterModel(model, filters)`. для больших файлов можно передать `parseExport(input, { onProgress })`; callback получает `phase`, `processed`, `total` и `ratio`. `import-worker.js` обрабатывает импорт в отдельном потоке. `demo-data.js` создаёт вымышленный пример локально. `app-motion.js` управляет событийными анимациями, `app-graph.js` и `app-exploration.js` — списком связанных узлов и пояснениями об импорте.
