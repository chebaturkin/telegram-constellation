# telegram constellation — дизайн улучшенной версии

## Цель

Сделать из текущего client-side MVP надёжный архивный атлас Telegram Desktop: пользователь выбирает локальный JSON, получает понятную карту связей и периодов, может безопасно исследовать срез, экспортировать его и в любой момент удалить данные. Интерфейс остаётся спокойным печатным атласом без технических мета-ярлыков, декоративных карточек, градиентов, glow и нейросетевой стилистики.

## Что улучшаем

- Импорт становится предсказуемым: предыдущая операция отменяется, слишком большой файл не может перезаписать состояние, Worker имеет безопасный fallback, ошибки формата не показывают сырой stack trace.
- Нормализатор принимает типичные формы Telegram Desktop, пропускает пустые/битые записи, корректно обрабатывает fallback-поля, даты и подписи, не хранит тексты сообщений.
- Фильтры пересобирают оба слоя графа без тихого возврата к исходной модели; диапазон дат сбрасывается при новом импорте, а текущий срез отражается в заголовке и статусе.
- Режим «Только связи» показывает только действительно видимые рёбра и их endpoints. Превью при наведении не остаётся после ухода курсора; выбранная точка сохраняется отдельно.
- Карта поддерживает понятное управление мышью, touch и клавиатурой. Для узлов используется компактная навигация фокуса, а live-регионы не создают шум для скринридеров.
- На мобильном экране импорт и карта встречаются раньше длинных справочных блоков; высота карты остаётся пригодной для чтения. Timeline привязывается к основной области атласа и не оставляет большого пустого промежутка.
- Панель инспектора показывает узел, сообщения, количество связей и период; текстовая альтернатива перечисляет текущие узлы и типы связей. Экспорт SVG/PNG всегда берёт текущий фильтрованный срез и не содержит тексты сообщений.
- Визуальная система остаётся единой: Newsreader Local для заголовков и пояснений, Commit Mono Local для чисел/подписей, цвета `#10212B`, `#E7DFC8`, `#C45236`, `#2F5D8A`, `#39434A`, тонкие правила и координатная сетка.

## Архитектура

`app-data.js` отвечает только за безопасный разбор, нормализацию агрегатов, построение связей и фильтрацию. `import-worker.js` читает ArrayBuffer и возвращает только прогресс/агрегированную модель. `app.js` держит состояние интерфейса, управляет импортом, рендерит SVG/timeline и экспортирует текущий срез. `index.html` содержит семантическую структуру, `styles.css` — дизайн-систему и responsive-правила.

Данные остаются в памяти страницы. Никаких `fetch`, API, аналитики, хранилища, аккаунтов или сетевых загрузок. Сообщение и исходное поле `text` удаляются сразу после извлечения технических признаков. Для больших экспортов модель не дублирует полные записи без необходимости.

## Пользовательский сценарий

1. Пользователь видит короткое объяснение приватности и выбирает или перетаскивает `result.json`.
2. Во время чтения видит фазу и процент; текущий импорт можно отменить. Ошибки возвращают понятное действие восстановления.
3. После загрузки получает карту, счётчики, текущий режим узлов, фильтры, временную шкалу и легенду.
4. Наведение даёт временное превью; клик или Enter закрепляет узел в инспекторе. Escape снимает выбор.
5. Фильтр по чату, участнику или датам сразу пересобирает вид. Сброс возвращает исходный слой.
6. Масштаб, перетаскивание, текстовая альтернатива и экспорт работают на текущем срезе.
7. «Удалить данные» останавливает импорт, очищает модель, фильтры, URL-состояние, инспектор и скачиваемые ссылки.

## Данные и правила нормализации

- Поддерживаются `chats.list`, один объект чата с `messages`, корневой массив сообщений и обёртка `result`.
- Не-объекты и service-события пропускаются. Если после очистки сообщений нет, возвращается `ExportFormatError` с кодом `NO_MESSAGES`.
- Для `from_id`, `from`, `author`, дат, reply и имён применяется fallback только после проверки непустого значения.
- Дата валидируется календарно до ISO-нормализации; `dateKey` и `date` всегда относятся к одному дню.
- Связи: reply, mention, общий чат и временная близость. Поиск mention-целей использует индексы участников, а общие связи ограничены уникальными парами.
- `filterModel` не скрывает ошибки: возвращает согласованную пустую модель или передаёт ошибку в UI как понятный статус.

## Состояния и доступность

Нужны отдельные состояния: до импорта, чтение, готово, пустой срез, ошибка формата, отмена. Статус и прогресс используют live-region только для фаз/ошибок. SVG узлы получают `aria-label`, но не превращают сотни точек в длинную Tab-цепочку: один активный узел в roving tabindex, стрелки перемещают фокус по видимым узлам.

Все интерактивные элементы имеют видимый focus-ring. `prefers-reduced-motion` выключает анимации. Цвет всегда поддержан формой, текстом или типом линии. Мобильный порядок: импорт → карта → параметры/фильтры → инспектор → timeline/легенда.
