# Telegram Constellation

локальный визуальный атлас Telegram-экспортов. выберите `result.json` из Telegram Desktop и спокойно разберите чаты, участников, связи и периоды прямо в браузере.

[открыть Telegram Constellation на GitHub Pages](https://chebaturkin.github.io/telegram-constellation/)

## приватность

- файл читается через браузерный File API и не отправляется на сервер;
- импорт не использует Telegram API, аккаунты, аналитику, AI или обязательный backend;
- исходные тексты сообщений не сохраняются в модели, URL, логах и экспортируемых SVG/PNG;
- после разбора остаются только имена, даты, счётчики, технические идентификаторы и типы связей;
- кнопка «удалить данные» очищает модель, фильтры, инспектор и временные ссылки из памяти страницы;
- неудачный новый импорт или отмена сохраняют уже открытую карту.

## как пользоваться

1. откройте страницу и выберите локальный `result.json` или перетащите его в область загрузки;
2. дождитесь разбора файла и изучите карту, легенду, текстовое описание и шкалу периодов;
3. фильтруйте по чату, участнику и датам, а затем скачайте текущий срез в SVG или PNG;
4. для нового файла выберите его снова. чтобы начать с чистого листа, нажмите «удалить данные».

период на шкале можно выбрать мышью или клавиатурой: он применит свои даты к текущему срезу. повторный выбор того же периода снимет диапазон.

## что поддерживается

нормализатор принимает типичные формы Telegram Desktop:

- `{ "chats": { "list": [...] } }` с чатами и массивами `messages`;
- один объект чата с `messages`;
- массив сообщений с полями `from`, `from_id`, `date`, `reply_to_message_id`, `entities` и метаданными чата.

карта строит связи по ответам, упоминаниям, общим чатам и близости по времени. размер узла показывает число сообщений, а цвет помогает увидеть относительную активность. в режиме «авто» смешанный экспорт открывает слой чатов, а один чат — слой участников.

пустые и повреждённые записи пропускаются. невалидные календарные даты не попадают на шкалу. если после очистки сообщений ничего не осталось, интерфейс показывает понятную ошибку и оставляет предыдущую карту нетронутой.

## запуск локально

для локальной проверки запустите статический сервер из корня проекта:

```bash
python3 -m http.server 4175
```

затем откройте `http://127.0.0.1:4175/index.html`. статический сервер нужен для ES-модулей и Web Worker; приложению не нужен backend.

## проверки

```bash
node --test scripts/data-tests.mjs
node scripts/design-copy-check.mjs
APP_PORT=4175 python3 scripts/smoke_test.py
APP_PORT=4178 python3 scripts/interaction_test.py
```

fixture-файлы лежат в `fixtures/`: `result-small.json` помогает быстро проверить карту, а `result-invalid.json` проверяет дружелюбную ошибку формата.

## ограничения

файл читается целиком в браузере. интерфейс показывает прогресс и принимает JSON размером до 250 МБ. ZIP-архив можно распаковать локально и выбрать `result.json`.

`app-data.js` экспортирует `parseExport(input)`, `normalizeModel(parsed)`, `deriveRelations(model)` и `filterModel(model, filters)`. для больших файлов можно передать `parseExport(input, { onProgress })`; callback получает `phase`, `processed`, `total` и `ratio`.

## визуальные правила

интерфейс говорит языком печатного атласа и читального зала: Newsreader для заголовков, Commit Mono для дат и чисел, спокойная бумажная палитра, тонкие линии и координатная сетка. подробные правила лежат в [`docs/DESIGN-RULES.md`](docs/DESIGN-RULES.md).
